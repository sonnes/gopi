The Layer

Must get across: one call takes a binding, the messages, and the options, and it returns a stream of events and then one message.

Today a flowchart joins seven boxes into one call box. The reader cannot see which part of the signature each box is, and two tables on the page repeat the same capability facts.

The Picture · replaces the diagram

A · on the siteSignature anatomy

Why: The reader sees the real signature and each argument opens into its type and its page, so the figure is also a map of the section. The return path comes out of the method name, and the events and the message sit in their real order. Cost: The brackets depend on the mono font width. The call must stay one short line.

BMachine I/O

Why: The reader gets the shape of a call at a glance: inputs, one box, outputs. The ticks say "many, small, in order" without naming the event types. Cost: It loses the signature, so the reader still has to map each input to an argument.

Optional Capabilities · new; merges the two tables

A · on the siteCapability matrix

Why: One grid answers both questions on the page: which interface a function needs, and which provider has it. The empty Speech column shows that no provider implements it. Cost: A new provider or capability adds a row or a column, and the column heads are already at the width limit.

BBadges per provider

Why: The reader who has already picked a provider reads one card and is done. Cost: The interface names are gone, and comparing providers across cards is slower than reading a column.
