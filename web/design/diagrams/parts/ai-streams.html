Streams

Must get across: a stream is the ordered events of one call, each tagged with the block it builds, and Wait gives the final message and error after them.

Today: three boxes and a list of event names in one tall box, so the reader cannot see time, which block each event feeds, or how deltas become the final message.

The Picture · replaces the top diagram

A · on the siteTimeline with lanes

Why: Time runs left to right and each ContentIndex gets its own lane, so the reader sees which block a delta feeds and how the buffer grows into the block of the final message. Cost: HTML grid only. Eight columns fill the width, so a longer example needs "..." columns.

BSequence diagram

Why: It shows the two goroutines and that the message and the error come back through Wait, not as an event. Cost: it shows only two events, so the lanes and the buffer are lost.

CTypewriter (CSS motion)

Why: The motion shows the one idea that a list cannot: deltas append to a buffer, and the end event closes the block. The still frame shows the finished blocks. Cost: motion on a docs page can distract, and it hides Wait.
