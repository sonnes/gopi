Textbook Ink

Each figure looks like a figure in a programming book: thin lines in the text color, serif labels, mono code, and a numbered caption.

Borrows from K&R, The Go Programming Language, and the Tufte books: trace tables with rules, curly braces, leader lines, and italic notes in the margin.

F1 · Streams · the events of one call

Reads as: a trace table from a book: one row for each event, and under the table the message holds the finished rows in the same columns. Cost: the block column repeats the text of the deltas, so a long payload has no room in the row.

F2 · Sessions · add context to a run

Reads as: one row for each entry, with the kind in small caps and in the line of its box, so the figure needs no color and no legend. Cost: the double line of the assistant box is a weak signal at this size, and the reader learns four line styles.

F3 · Tools · two failure channels

Reads as: a flow chart without boxes, where the error result loops back to the model and the Go error stops at a bar on the right edge. Cost: the bar is a convention, so the reader depends on the label "run ends" to read it.

On a Page · F3 next to body text

A tool run ends in one of two ways. If the tool returns an error result, the agent sends the result to the model, and the model can correct the call. If the tool returns a Go error, the run stops and Run returns the error. Figure 3 shows the two paths.

Reads as: the figure has the same ink and the same weight as the text, so it reads as part of the page. Cost: the serif labels are a third face on a page that already sets a sans and a mono.
