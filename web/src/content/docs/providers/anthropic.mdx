## Thinking

`ai.Thinking` maps to the effort of the API. A level that the provider does not know fails the call before the request.

On a model that always thinks, the provider sends the effort as a system message before each assistant message. Each assistant message keeps the effort that it used, so a change of level does not change the cached prefix. `msg.Effort` holds the effort that the API used.

A thinking block comes back signed. Send the assistant message back unchanged, and the API verifies it. If a block does not match its prefix, the API drops the block and the call goes on. [Stream a Response](../guides/stream-a-response.mdx) shows the round trip.

Put the stable part of a prompt first, so the prefix stays the same between calls. `ai.CacheShort` keeps the prefix for 5 minutes, and `ai.CacheLong` for 1 hour. `ai.CacheNone` sends no marks. `Usage.CacheRead`, `Usage.CacheWrite`, and `Usage.CacheWriteLong` show the effect.

## System Messages

Fable 5.1, Opus 5.5, Opus 5, and Sonnet 5.5 take a system message in the conversation, and the provider sends it in its place. On these models, a tool change goes in place too, so the cached prefix stays the same. Every other model gets the text as a `<system-reminder>` in a user message, and the tool list of the request holds the current tools.

## Objects

`ai.GenerateObject` uses structured outputs. The schema comes from your struct.

## Token Counts

`ai.CountTokens` sends the same messages, system prompt, tools, and thinking config as a call, so the count matches the call.

## Errors

An API error wraps `anthropic.Error`. Read the status code with `errors.As`.

```go
var apiErr *anthropic.Error
if errors.As(err, &apiErr) {
	fmt.Println(apiErr.StatusCode, apiErr.RequestID)
}
```

With `ai.MaxRetries`, the provider sends the request again after a rate limit, an overload, or a server error. It retries only before the first event, and it waits as long as the server asks, up to `ai.MaxRetryDelay`.

A refusal is not an error. The message has the stop reason `refusal`, and `msg.StopDetail` holds the reason that the API gave.
