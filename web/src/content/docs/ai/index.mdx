`pkg/ai` holds the types that name a model call. A provider serves the call. A binding pairs a model with a provider. The messages go in, and a stream of events and one final message come out.

## The Abstractions

| Abstraction | Meaning                                                    | Page                     |
| ----------- | ---------------------------------------------------------- | ------------------------ |
| model       | One named model that a provider serves                     | [Models](models.mdx)     |
| provider    | One backend that answers a model call                      | [Models](models.mdx)     |
| message     | One turn of a conversation, with a role and content blocks | [Messages](messages.mdx) |
| option      | One typed setting of a call                                | [Options](options.mdx)   |
| stream      | The events of one call, read in order, then the message    | [Streams](streams.mdx)   |
| tool        | One function that a model can call                         | [Tools](../tool/index.mdx)       |

The glossary in [docs/README.md](../../../../../docs/README.md) keeps one name for each thing.

## The Optional Capabilities

A provider always streams text. It can also do these. `ai.GenerateObject` and `ai.CountTokens` are functions that take a language model and assert the interface on its provider. If the provider lacks the interface, the function returns an error. Images and speech have their own bindings, `ai.ImageModel` and `ai.SpeechModel`. Each binding takes only a provider that implements its interface, so a binding to a provider without it does not compile.

A provider can also list the models that its key can call, with `ModelLister`. The list belongs to the provider and not to one model, so it is a method on the provider and not a function on the binding. All three providers implement it.

[Anthropic](../providers/anthropic.mdx), [OpenAI](../providers/openai.mdx), and [OpenAI Chat](../providers/openai-chat.mdx) show what each provider adds to a call.
