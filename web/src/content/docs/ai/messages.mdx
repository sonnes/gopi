A content block is text, thinking, a tool call, or a file. A file is an image or a PDF, in a user message or a tool result. A model holds no state, so each call sends every message of the conversation.

## Build

```go
ai.UserMessage("What is the weather in Lisbon?")
ai.AssistantMessage(ai.Text{Text: "Let me check."}, call)
ai.ToolResultMessage(call.ID, ai.Text{Text: `{"temp_c":21}`})
ai.SystemMessage(ai.Text{Text: "Answer in French from now on."})
```

## System Messages

The `ai.SystemPrompt` option is the prompt in front of the conversation. A system message adds instructions from its place, so you can change the prompt in the middle of a conversation without a change to the start of the request.

A provider sends the message with the system role of its API: `system` for `anthropic` and `openaichat`, `developer` for `openai`. The message waits until the next assistant message, so it never comes between a tool call and its result.

A model that does not take a system message inside the conversation gets the text as a `<system-reminder>` in a user message. The provider knows which models take one, so your code sends the same messages to every model.

A system message holds other blocks too. `ai.Section` and `ai.SectionRemoved` change a named part of the prompt. `ai.ToolAdded` and `ai.ToolRemoved` change the tools that the model can call. One message can hold any mix, in order:

```go
ai.SystemMessage(
	ai.SectionRemoved{Name: "env"},
	ai.Section{Name: "repo", Text: "<repo>gopi</repo>"},
	ai.ToolAdded{Tool: weather.Info()},
)
```

## Read

```go
msg.Text()        // the text blocks, joined
msg.ToolCalls()   // the tool call blocks, in order
msg.StopReason    // why the model stopped
msg.StopDetail    // the reason that the API gave, if any
msg.Effort        // the effort that the API used, such as "high"
msg.Usage         // the token counts of this response
```

## Stop Reasons

<StopFork
  alt="msg.StopReason forks four ways. stop: show the text. tool_use: run each tool call, send the results, and call the model again. length: raise the cap, or ask the model to continue. refusal: do not run its tool calls."
  from="msg.StopReason"
  outcomes={[
    { value: "stop", action: "show the text" },
    { value: "tool_use", action: "run each tool call, send the results", loop: "call again" },
    { value: "length", action: "raise the cap, or ask it to continue" },
    { value: "refusal", action: "do not run its tool calls", bad: true },
  ]}
/>

`length` means that the output cap or the context is full. `refusal` means that a safety classifier stopped the turn, and `msg.StopDetail` holds the reason that the API gave.

A provider never sets `aborted` or `error`. A caller that keeps a partial message sets one of them, so a later reader knows that the message is incomplete. The [agent](../agent/index.mdx) does this when a cancel or a failure cuts a reply short, and `error` puts the error in `msg.StopDetail`.

## JSON

A message round-trips through JSON, so a conversation needs no schema of your own to store it.

```go
data, err := json.Marshal(messages)
err = os.WriteFile(path, data, 0o600)

var back []ai.Message
err = json.Unmarshal(data, &back)
```

A saved message reads back with every block, or the read fails, for example when an older build of gopi reads a newer block type. A field that does not apply to the role is left out, so a user message has no usage. The timestamp is in UTC. The program is [examples/save-a-conversation/main.go](../../../../../examples/save-a-conversation/main.go).
