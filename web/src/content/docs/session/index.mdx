## The Log

`agent.New` runs over a log in memory, and the log ends with the process. `agent.Durable` opens the log of a session in a store, so a later process resumes it. `a.Log()` returns the log of an agent.

```go
a, err := agent.Durable(ctx, model, "user-42", agent.Store(store))

entries := a.Log().Entries() // every stored entry, in append order
msgs := a.Log().Messages()   // what the model reads
```

A session has one writer. Two logs on one session interleave their entries, and a provider can reject the result.

## Entries

An entry holds one message, or the data of a custom entry. You set the author and the ephemeral mark. The log sets the ID and the time.

```go
session.Text("hi", session.Author("user-42"))
session.Text("The time is 9:14 AM.", session.Ephemeral())
session.NewEntry(msg, session.Author("importer"))
marker, err := session.Custom("compaction", summary)
```

To add entries, pass them to `Run`, `Steer`, or `FollowUp` of the [agent](../agent/index.mdx), or return them from an `AfterTurn` or `BeforeStop` [hook](../agent/hooks.mdx).

The author is a user ID or an agent name. The `Name` option of an agent sets the author of each assistant message and tool result. A UI can choose which entries to show by the author.

A custom entry keeps a fact of the application in its place among the messages, such as the summary of a compaction. `Messages` skips it. The kind `gopi` and each kind that starts with `gopi.` belong to gopi.

## Values

A value has a namespace, a key, and a type. Declare it once, then read and write it through the log. The store keeps it as JSON.

```go
var title = session.Value[string]{Namespace: "app.title"}

err := title.Set(ctx, a.Log(), "Trip to Lisbon")
t, ok, err := title.Get(a.Log())
err = title.Delete(ctx, a.Log())
```

| Call     | Result                                                                    |
| -------- | ------------------------------------------------------------------------- |
| `Set`    | Encodes the value as JSON and stores it. A later set replaces it          |
| `Get`    | Returns the value. `ok` is false if the value is not set                  |
| `Delete` | Removes the value. A delete of a value that is not set does nothing       |
| `Read`   | Returns the value from a `session.Snapshot`, before you open the session  |

```go
snap, err := store.Load(ctx, "user-42")
t, ok, err := title.Read(snap)
```

The JSONL store can repair the file in `Load`. Call `Load` only when no other process writes the session.

A key names one value in a namespace, for example a label for each entry: `session.Value[string]{Namespace: "app.label", Key: entryID}`. The namespace `gopi` and each namespace that starts with `gopi.` belong to gopi. To give the model a value, append it as an entry.

## In a Hook

A hook reads the session from `State.Log()`: the entries, the messages, and the values. It can set and delete values. It cannot append an entry. To add entries, return them from an `AfterTurn` or `BeforeStop` hook, or queue them with [`s.Steer` or `s.FollowUp`](../agent/hooks.mdx#steer-from-a-hook).

```go
var turns = session.Value[int]{Namespace: "app.turns"}

count := agent.AfterTurn(func(ctx context.Context, s agent.State) ([]session.Entry, error) {
	n, _, err := turns.Get(s.Log())
	if err != nil {
		return nil, err
	}
	return nil, turns.Set(ctx, s.Log(), n+1)
})
```

A value is in the store when `Set` returns, also if the run fails after it. A state that a viewer decoded from JSON has no log, so its `Log` returns nil.

## After a Crash

A crash loses at most the message in flight. It can leave a tool call with no result, and a provider rejects that.

If a run fails in its tool calls and the process lives on, the next run stores the error results first, with their events.

## Stores

| Store                      | Keeps                              | Use it for                 |
| -------------------------- | ---------------------------------- | -------------------------- |
| `session.NewMemoryStore()` | Maps in process memory             | Tests. `Durable` uses it when you set no `Store` |
| `jsonl.New(dir)`           | One append-only file per session   | One process on one machine |

For a service, implement [`session.Storer`](https://pkg.go.dev/github.com/sonnes/gopi/pkg/session#Storer) over your database.

## The JSONL File

The file of a session is `<dir>/<id>.jsonl`. The first line is the record. Each line after it is one entry or one value write. The store never rewrites a line.

- A custom entry is a `message` line too.
- The load replays the value lines in order, so a later set replaces an earlier one. Each set adds a line.
- If a complete line does not decode, the load fails.
- An ID that holds `/` or `\`, or that is `.` or `..`, is an error.
