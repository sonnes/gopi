`tool.New` turns a Go function into a tool. The schema comes from the input struct, so there is none to write.

```go
type WeatherIn struct {
	City string `json:"city" jsonschema:"the city to look up"`
}

var weather = tool.New(
	"weather",
	func(ctx context.Context, in WeatherIn) (WeatherOut, error) {
		return WeatherOut{City: in.City, TempC: 21}, nil
	},
	tool.Description("Get the current weather of a city."),
)
```

`tool.Func` is the raw form. Use it when the schema is not a struct, or when the input is not JSON that a struct can hold.

```go
var clock = tool.Func(
	"clock",
	func(ctx context.Context, call ai.ToolCall) (ai.ToolResult, error) {
		now := time.Now().Format(time.RFC3339)
		return ai.ToolResult{Content: []ai.Content{ai.Text{Text: now}}}, nil
	},
	tool.Description("Get the current time in RFC 3339."),
	tool.InputSchema(&jsonschema.Schema{Type: "object"}),
)
```

A tool has two failure channels. An error result goes to the model, which corrects the call. A Go error is for a middleware, such as a retry. The loop then gives its text to the model, unless the context is canceled.

| Return                         | Means                                       |
| ------------------------------ | ------------------------------------------- |
| `ToolResult{IsError: true}, nil` | The model reads it and calls again           |
| `ToolResult{}, err`              | A middleware can retry. Then the model reads it |
| Any return after `ctx` is canceled | The loop stops                             |

`tool.New` turns an error from the function into an error result. Return a Go error from a raw tool when a retry can help, such as a transport that is down.

## Run the Loop

Send the infos, run every call the model makes, append each result, and call again. The loop ends when the stop reason is not `tool_use`. A refusal can hold tool calls, so the loop does not run the calls of any other stop. An [agent](../agent/index.mdx) runs this loop for you.

```go
for {
	msg, err := model.StreamText(ctx, messages, ai.Tools(infos)).Wait()
	if err != nil {
		log.Fatal(err)
	}
	messages = append(messages, *msg)
	if msg.StopReason != ai.StopReasonToolUse {
		fmt.Println(msg.Text())
		return
	}

	for _, call := range msg.ToolCalls() {
		messages = append(messages, runTool(ctx, tools, call))
	}
}
```

An unknown tool name goes back as an error result, so the model can pick another tool.

```go
m := ai.ToolResultMessage(call.ID, ai.Text{Text: "unknown tool " + call.Name})
m.IsError = true
```

## Guard Every Tool

A middleware sees `Info` and `Run`, so it can edit the description, deny a call, retry a run, or append to a result. `tool.Wrap` keeps the info of the tool and swaps its run function. `Deny` puts its names in a set, `denied`, and returns this middleware:

```go
return func(next tool.Tool) tool.Tool {
	return tool.Wrap(next, func(ctx context.Context, call ai.ToolCall) (ai.ToolResult, error) {
		if denied[call.Name] {
			return ai.ToolResult{
				Content: []ai.Content{ai.Text{Text: "tool " + call.Name + " is not allowed"}},
				IsError: true,
			}, nil
		}
		return next.Run(ctx, call)
	})
}
```

`tool.Chain` applies one chain to a tool. The first middleware is the outermost, so `Log` sees the result of `Deny`. `Log` also adds `(logged)` to each description, so the model sees the change. `Retry` runs the tool again only on a Go error. An error result passes through to the model.

```go
func guard(t tool.Tool) tool.Tool {
	return tool.Chain(t,
		Log(os.Stdout),
		Deny("rm"),
		Remind("Do not delete files."),
		Retry(2),
	)
}
```

A middleware that appends to every result is a place for a rule the model must obey. `Remind` does this after a successful run:

```go
res, err := next.Run(ctx, call)
if err != nil {
	return res, err
}
res.Content = append(res.Content, ai.Text{Text: text})
return res, nil
```
