:::note
The program in this guide needs no key. Its model is a fake provider that sends scripted replies.
:::

`agent.New` takes a model and options. `Run` takes the input as entries and returns a stream. `Wait` returns the messages that the run produced.

```go
a := agent.New(lm, agent.Toolset(weather))

msgs, err := a.Run(ctx, session.Text("Is it warmer in Lisbon or in Oslo?")).Wait()
```

The agent calls the model, runs each tool that the model calls, and calls the model again. The run stops when the model makes no tool call.

## Pick the Model

The fake provider answers each model call with the next scripted reply. The first reply calls the weather tool for two cities. The second reply is the answer.

```go
lm := ai.LanguageModel{
	Model: ai.Model{ID: "fake"},
	Provider: &fake.Provider{Replies: []ai.Message{
		reply(120, 30, call("call_1", "Lisbon"), call("call_2", "Oslo")),
		reply(180, 12, ai.Text{Text: "Lisbon is warmer: 21 degrees against 9."}),
	}},
}
```

To call a real model, bind a provider. This model needs `ANTHROPIC_API_KEY`.

```go
model := ai.LanguageModel{
	Model:    ai.Model{ID: "claude-sonnet-5"},
	Provider: anthropic.New(),
}
```

## Set the Options

```go
a := agent.New(lm,
	agent.Toolset(weather),
	agent.System(func(context.Context) ([]ai.Section, error) {
		return []ai.Section{{Name: "base", Text: "Answer in one sentence."}}, nil
	}),
	capTurns,
)
```

`Toolset` gives the agent its tools. `System` builds the prompt as a list of [sections](../agent/sections.mdx) before each model call. [Agents](../agent/index.mdx) lists each option.

To guard one tool, wrap it in a middleware. [Use Tools](use-tools.mdx) shows how. To guard every tool of the agent, use a [hook](../agent/hooks.mdx).

## Cap the Turns

The agent has no cap on the turns of a run. A `BeforeCall` hook runs before each model call, and `State.Turn()` is the turn of that call. If the hook returns an error, the run fails before the call.

```go
capTurns := agent.BeforeCall(func(ctx context.Context, s agent.State, r agent.Request) (agent.Request, error) {
	if s.Turn() > maxTurns {
		return r, errors.New("the run used too many turns")
	}
	return r, nil
})
```

## Read the Events

Each event is its own type. Read the stream with a type switch.

```go
switch ev := ev.(type) {
case agent.EventMessageUpdate:
	if ev.AssistantEvent.Type == ai.EventTextDelta {
		fmt.Print(ev.AssistantEvent.Delta)
	}
case agent.EventToolExecutionStart:
	fmt.Printf("-> %s %s\n", ev.ToolName, ev.Args)
case agent.EventToolExecutionEnd:
	fmt.Printf("<- %s error=%v\n", ev.ToolName, ev.Result.IsError)
case agent.EventAgentEnd:
	fmt.Printf("\n%d tokens in, %d tokens out\n", ev.Usage.Input, ev.Usage.Output)
}
```

| Event                     | Carries                                                    |
| ------------------------- | ---------------------------------------------------------- |
| `EventMessageUpdate`      | One model event and a snapshot of the partial message      |
| `EventToolExecutionStart` | The name and the input of one tool call                    |
| `EventToolExecutionEnd`   | The result of one tool call                                |
| `EventMessageEnd`         | The final message, after the log stores it                 |
| `EventAgentEnd`           | The usage of the run, summed, and the error of a run that failed |

## Continue a Run

If a failure stops a run, call `Run` with no entries. The run continues from the last message of the history.

```go
stream := a.Run(ctx)
```

## Keep the History

The log of the agent keeps the history. It stores each message before its `message_end` event, so it has every message of the run.

```go
fmt.Printf("%d entries in the log\n", len(a.Log().Entries()))
```

The log of `agent.New` is in memory and ends with the process. To keep the history across processes, use `agent.Durable` with a store. [Keep a Session](keep-a-session.mdx) shows how.

## Read the Output

- The two `->` lines are the calls of the first turn. They start in call order. The calls run at the same time, so the `<-` lines can come in either order. The tool results go to the log in the same order as the `<-` lines.
- The answer prints as it streams.
- The token line comes from `agent_end`. It is the sum of the usage of the two model calls.
- The role lines list the history. The first is the `system` message that `System` built. Then come the question, the assistant message with the calls, the two tool results, and the answer.
- The last line counts the entries of the log. The count is the same as the number of role lines.
