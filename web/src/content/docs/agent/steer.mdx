---
title: Steer and Follow-Up
summary: A steer is a message that the agent reads before its next model call. A follow-up is a message that the agent reads when the run would stop.
---

import Lanes from "../../../components/figures/Lanes.astro";

Use `Steer` and `FollowUp` when a run is active and you have a message for the agent, such as a correction or the next task. Without them, you wait for the run to end, because a second `Run` fails while a run is active. Each call adds messages to a queue. The agent drains a queue at fixed points of the loop, and it takes every message of the queue at one time.

## Steer

```go
a.Steer(ai.UserMessage("Use the v2 API."))
```

The agent drains the steer queue after the turn in progress. Every tool call of that turn runs first. If the queue has messages, the run goes on, also when the turn made no tool calls.

A steer from before `Run` goes after the input of `Run`.

## Follow-Up

```go
a.FollowUp(ai.UserMessage("Then add a test."))
```

The agent drains the follow-up queue when the run would stop: the turn made no tool calls, and the steer queue is empty. The agent drains it before the [`BeforeStop` hooks](hooks.mdx) run. A `BeforeStop` hook runs only if the follow-up queue is empty.

## Rules

The agent reads each queued message in this run or the next one, also after a failure, unless the process stops first.

- `Steer` and `FollowUp` do not start a run. If no run is active, call `Run`.
- The queues are in memory only. A snapshot of the [state](events.mdx#state) does not hold them.
- You can call `Steer` and `FollowUp` from any goroutine.
- Each message from a queue arrives on the [stream](events.mdx) as a `message_start` and a `message_end`, after the `turn_start` of the turn that reads it.
