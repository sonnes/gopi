An agent calls the model and runs the tools that the model calls. Then it calls the model again with the results. Each message goes into the history when the message is complete.

A turn is one model call and the tool calls that it makes. A [steer message](steer.mdx), a follow-up, or a `BeforeStop` [hook](hooks.mdx) can also start the next turn.

## Create an Agent

`agent.New` takes a model and options. It does no I/O, so it takes no context and returns no error.

```go
a := agent.New(lm,
	agent.Toolset(weather),
	agent.System(func(context.Context) ([]ai.Section, error) {
		return []ai.Section{{Name: "base", Text: "Answer in one sentence."}}, nil
	}),
)
```

## Options

| Option              | Sets                                                            |
| ------------------- | --------------------------------------------------------------- |
| `History(msgs...)`  | The messages that the agent starts with, such as a saved conversation |
| `Toolset(tools...)` | The tools of the agent. Each name must be unique. A deferred tool waits for the [search](tool-changes.mdx) |
| `System(fn)`        | The system prompt as [sections](sections.mdx), built before each model call |
| `MaxTokens(n)`      | The maximum output tokens of every model call                    |
| `Thinking(level)`   | The thinking level of every model call                           |
| `Hooks(hs...)`      | [Hooks](hooks.mdx) that change the loop at six points            |
| `BeforeCall(fn)`, `AfterCall(fn)`, `BeforeTool(fn)`, `AfterTool(fn)`, `AfterTurn(fn)`, `BeforeStop(fn)` | One hook at one point of the loop |

## Run

`Run` adds the messages to the history and returns a stream of [events](events.mdx). `Wait` returns the messages that the run produced. The input is not in that result, because you already have it.

```go
stream := a.Run(ctx, ai.UserMessage("Is it warmer in Lisbon or in Oslo?"))
msgs, err := stream.Wait()
```

With no messages, the run continues from the last message of the history. So after a failure stops a run, `a.Run(ctx)` continues it.

## Rules

- Runs on one agent are sequential. If a run is active, a second `Run` fails on its stream, with no event.
- Each run that starts ends with `agent_end`, also a run that fails.
- The tool calls of one message run at the same time. The results go into the history in call order. If a message calls a tool marked `tool.Sequential()`, every call of that message runs in order.
- A Go error from a tool goes to the model as an error result, and the run goes on. If the context of the run is canceled, the run fails.
- If the model calls a tool that the agent does not have, the model gets an error result.
- If two tools have the same name, `New` panics.
- The agent has no cap on the turns of a run. To set a cap, add a `BeforeCall` hook that reads `State.Turn()` and returns an error.

## Save and Resume

`a.State().Messages()` returns the history. Each message of the history arrives on the stream as one `message_end` event. This includes the input. To save a conversation, save the message of each `message_end`.

```go
case agent.EventMessageEnd:
	saved = append(saved, ev.Message)
```

To resume, give the saved messages to `History`.

```go
resumed := agent.New(lm, agent.History(saved...), agent.Toolset(weather))
```

If the first message is a system message, it is the base of the prompt. If `Toolset` adds or removes a tool after the base, the agent declares the difference as a [tool change](tool-changes.mdx).
