```go
a := agent.New(lm, agent.Toolset(weather))

a, err := agent.Durable(ctx, lm, "user-42", agent.Store(store), agent.Toolset(weather))
```

`Durable` creates a new session, or resumes an existing one after its last entry. [Tool Changes](tool-changes.mdx#resume-a-session) says what a resumed session does with its tools. [Sessions](../session/index.mdx) shows the log and the stores.

## Options

| Option              | Sets                                                            | Default |
| ------------------- | --------------------------------------------------------------- | ------- |
| `Store(s)`          | The store of a `Durable` agent                                  | A memory store |
| `Name(s)`           | The author of each assistant message and tool result            | Empty |
| `Toolset(tools...)` | The tools of the agent, each with a unique name. A deferred tool waits for the [search](tool-changes.mdx) | None |
| `System(fn)`        | The [sections](sections.mdx) of the prompt, built before each model call | The sections of the log |
| `MaxTokens(n)`      | The maximum output tokens of every model call                   | The model decides |
| `Thinking(level)`   | The thinking level of every model call                          | The model decides |
| `Hooks(hs...)`      | [Hooks](hooks.mdx) that change the loop                         | None |
| `BeforeCall(fn)` and the other points | One hook at one point of the loop             | None |
| `OnClose(fn)`       | A function that `Close` runs once, to release what the tools hold | None |

## Run

`Run` takes [entries](../session/index.mdx#entries), so you can set the author of each input and mark the ephemeral inputs. It adds them to the log and returns a stream of [events](events.mdx). `Wait` returns the messages that the run produced, without the input.

```go
stream := a.Run(ctx, session.Text("Is it warmer in Lisbon or in Oslo?"))
msgs, err := stream.Wait()
```

With no entries, the run continues from the last message of the history. So after a failure stops a run, `a.Run(ctx)` continues it.

## Rules

The model reads a result for each of its tool calls. If a failure stops a call, that result is an error.

- Runs on one agent are sequential. If a run is active, a second `Run` fails on its stream, with no event.
- The tool calls of one message run at the same time, and each result goes to the log when its call finishes. If a message calls a tool marked `tool.Sequential()`, every call of that message runs in order.
- The log stores each message before its `message_end` event. If the store fails, the run fails.
- If a run stops before a tool call has a result, the next run gives it the error result "tool execution interrupted".
- A Go error from a tool, or a call to a tool that the agent does not have, goes to the model as an error result. If the context of the run is canceled, the run fails.
- If two tools have the same name, `New` panics, and `Durable` returns an error.
