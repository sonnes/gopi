An agent reads its history from a log, calls the model, and runs the tools that the model calls. Then it calls the model again with the results. Each message goes to the log when the message is complete.

A turn is one model call and the tool calls that it makes. A [steer message](steer.mdx), a follow-up, or a `BeforeStop` [hook](hooks.mdx) can also start the next turn.

```go
a := agent.New(lm, agent.Toolset(weather))

a, err := agent.Durable(ctx, lm, "user-42", agent.Store(store), agent.Toolset(weather))
```

`Durable` needs a session ID. It is the one constructor that does I/O, so it is the one that takes a context and returns an error. [Sessions](../session/index.mdx) shows the log and the stores.

## Options

| Option              | Sets                                                            |
| ------------------- | --------------------------------------------------------------- |
| `Store(s)`          | The store of a `Durable` agent. The default is a memory store    |
| `Name(s)`           | The author of each assistant message and tool result            |
| `Toolset(tools...)` | The tools of the agent. Each name must be unique. A deferred tool waits for the [search](tool-changes.mdx) |
| `System(fn)`        | The system prompt as [sections](sections.mdx), built before each model call |
| `MaxTokens(n)`      | The maximum output tokens of every model call                    |
| `Thinking(level)`   | The thinking level of every model call                           |
| `Hooks(hs...)`      | [Hooks](hooks.mdx) that change the loop at six points            |
| `BeforeCall(fn)`, `AfterCall(fn)`, `BeforeTool(fn)`, `AfterTool(fn)`, `AfterTurn(fn)`, `BeforeStop(fn)` | One hook at one point of the loop |

## Run

`Run` takes [entries](../session/index.mdx#entries), so you can set the author of each input and mark the ephemeral inputs. It adds them to the log and returns a stream of [events](events.mdx). `Wait` returns the messages that the run produced. The input is not in that result, because you already have it.

```go
stream := a.Run(ctx, session.Text("Is it warmer in Lisbon or in Oslo?"))
msgs, err := stream.Wait()
```

With no entries, the run continues from the last message of the history. So after a failure stops a run, `a.Run(ctx)` continues it.

## Rules

The model reads a result for each of its tool calls, and if a failure stops a call, that result is an error.

- Runs on one agent are sequential. If a run is active, a second `Run` fails on its stream, with no event.
- The tool calls of one message run at the same time. Each result goes to the log when its call finishes, so the results are in the order in which the calls finish. If a message calls a tool marked `tool.Sequential()`, every call of that message runs in order.
- The log stores each message before its `message_end` event. If the store fails, the run fails.
- If a tool call has no result, because a run failed in its tools or the process stopped, the next run gives it the error result "tool execution interrupted".
- A Go error from a tool, or a call to a tool that the agent does not have, goes to the model as an error result, and the run goes on. If the context of the run is canceled, the run fails.
- If two tools have the same name, `New` panics, and `Durable` returns an error.
- The agent has no cap on the turns of a run. A `BeforeCall` [hook](hooks.mdx) can set one.

## Resume a Session

`Durable` resumes a session after its last entry. The first message of the session is the base of the prompt. If `Toolset` adds or removes a tool after the base, the agent declares the difference as a [tool change](tool-changes.mdx). The agent runs each successful `tool_search` call of the log again, so the tools that a search loaded stay loaded.
