Split the system prompt into sections when a part of it changes during a conversation, such as a todo list or a mode. With one section, each change sends the whole prompt again. Without `agent.System`, the agent keeps the prompt that the history holds.

Before each model call, the agent compares the sections with the sections of the history. If they differ, the agent adds one system message with the change. The message goes after `turn_start` and before the new messages of the turn.

## Set the Sections

Give `agent.System` a function that returns the sections in order. The agent calls the function before each model call.

```go
a := agent.New(model,
	agent.System(func(ctx context.Context) ([]ai.Section, error) {
		return []ai.Section{
			{Name: "base", Text: "You are a coding agent."},
			{Name: "todos", Text: "<todos>\n" + todos() + "\n</todos>"},
		}, nil
	}),
)
```

Put each section in a tag, or start it with a heading. Then the model can match a change to the old text.

## The Base

The first change of a new history is the base. It is the first message of the history, with every section and every tool. Each model call sends the base as `ai.SystemPrompt` and `ai.Tools`. The provider puts it in the system prompt and the tool list of its API.

## The Change

Each later change is one system message. The blocks of a section change come first:

| The function returns              | The system message holds                                 |
| --------------------------------- | -------------------------------------------------------- |
| The same sections                 | No message                                               |
| A changed text                    | An `ai.Section` with the new text, in its place          |
| No section with a known name      | An `ai.SectionRemoved` block                             |
| A new name, after the others      | An `ai.Section`, at the end                              |
| An order that a change cannot keep | An `ai.SectionRemoved` for each section, then every section again |

If the tools changed too, the same message holds the [tool change](tool-changes.mdx), after the sections. A turn adds one system message at most.

## The Frame

A provider sends each later change in its place in the messages. It frames a new or changed section by its name:

```
Updated system prompt section "todos":

<todos>
- [x] read the tests
</todos>
```

A removal reads `Removed system prompt section "todos".` A model that takes no system message in the conversation gets this text as a `<system-reminder>` in a user message.

## Claude Code and Codex

`claude.Sections` and `codex.Sections` take the same function. The agent calls it before each run. The first sections go in the prompt of the CLI. Claude Code gets each later change as a `<system-reminder>` before the input of the run. Codex gets it as a developer message before the turn. `claude.System` and `codex.System` give one fixed section.

## Resume a Session

To keep a conversation and resume it later, open it with `agent.Durable` and a store.

```go
a, err := agent.Durable(ctx, model, "user-42",
	agent.Store(store),
	agent.System(prompt),
)
```

The first message of the session stays the base. The agent reads the sections from the history, so it adds a change only if the prompt differs.

## Rules

A section change keeps the cache of the base and the history, unless the provider sends a new tool list on the same call.

- If the function returns an error, the run fails before the model call.
