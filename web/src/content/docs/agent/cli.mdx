## Start One

The CLI must be installed and logged in. The first run starts the CLI, and `Close` stops it.

```go
a := codex.New(
	codex.Dir("."),
	codex.Sandbox(codex.SandboxWorkspaceWrite),
)
defer a.Close()

msgs, err := a.Run(ctx, session.Text("Add a test for Parse.")).Wait()
```

`claude.New` takes the same shared options. Read the events of a run as you read the events of an agent. [Run an Agent](../guides/run-an-agent.mdx) shows how.

## Options

| Option                             | Package | Sets                                                        |
| ---------------------------------- | ------- | ----------------------------------------------------------- |
| `Store(s)`, `Name(s)`              | both    | The same as for `agent.Agent`                               |
| `Binary(path)`                     | both    | The path of the CLI. The default is `codex` or `claude` on `PATH` |
| `Dir(path)`                        | both    | The working directory of the CLI                            |
| `Model(name)`                      | both    | The model of the CLI                                        |
| `System(s)`                        | both    | Instructions that the CLI adds to its own prompt            |
| `Thinking(level)`                  | both    | The reasoning effort of the CLI. For Claude Code, `ai.ThinkingOff` turns thinking off |
| `Env(kv...)`                       | both    | More environment variables for the CLI                      |
| `Approve(fn)`                      | both    | The function that answers each approval request             |
| `Hooks(hs...)`                     | both    | [Hooks](hooks.mdx#hooks-on-a-cli-agent) that the CLI calls  |
| `HookCommand(path)`                | codex   | The `gopi` binary that relays a hook. The default is `gopi` on `PATH`. A run with hooks fails if the binary is missing |
| `Sandbox(mode)`, `Policy(policy)`  | codex   | What a command can touch, and when the CLI asks             |
| `PermissionMode(mode)`             | claude  | Which tools the CLI runs without a prompt                   |
| `AllowedTools(names...)`, `DisallowedTools(names...)` | claude | The tools that the CLI runs without a prompt, and the tools that it cannot use |

## Tools and Prompts

The CLI runs its own tools. Each tool call of the CLI becomes a tool call in an assistant message, then a tool result. So `tool_execution_start` and `tool_execution_end` report it.

| Codex item    | `ToolName`         |
| ------------- | ------------------ |
| command       | `bash`             |
| file change   | `apply_patch`      |
| MCP tool call | `<server>__<tool>` |
| web search    | `web_search`       |

Claude Code reports the names of its own tools, such as `Bash` and `Edit`.

`Approve` answers each approval request of Codex and each permission prompt of Claude Code. It takes an `agent.ApproveFunc`, the same function that the harness takes. The function gets an `agent.ApprovalRequest`: the tool call, with the name in the table above, and the reason of the CLI. The CLI waits for the answer, so the function must return when its context ends. Without the function, the agent refuses each request. Codex declines a file change request that comes before its item, and the function does not see it.

```go
a := claude.New(
	claude.AllowedTools("Read", "Grep"),
	claude.Approve(func(ctx context.Context, req agent.ApprovalRequest) (agent.Decision, error) {
		if req.Call.Name == "Bash" && !confirm(req.Call.Input) {
			return agent.Decision{Message: "The user refused the command."}, nil
		}
		return agent.Decision{Allow: true}, nil
	}),
)
```

A `Decision` with no `Allow` denies the call. Claude Code sends its `Message` to the model, and Codex has no field for it. With `Always`, the CLI also allows the calls that it matches to this call, until the session ends. Claude Code keeps the rule for the session only and writes no settings file. A rule of Claude Code can change the mode of the session, such as to `acceptEdits` after an edit. If Claude Code offers no "allow always" for the call, the request has `NoAlways`, and `Always` allows only this call. On Claude Code, `Always` with a new `Input` allows only this call. Codex cannot change the input of an action, so a decision with an `Input` declines the action.

To let a CLI act with no request, set `Policy(codex.ApprovalNever)` and a `Sandbox` mode for Codex. For Claude Code, set a `PermissionMode` or `AllowedTools`.

:::caution
Do not use `SandboxDangerFullAccess` or `PermissionBypass` outside a sandbox. With these modes, the CLI can run any command on the machine.
:::

## Sessions

`Durable` keeps the thread ID of Codex, or the session ID of Claude Code, as a [value](../session/index.mdx) of the session. A second `Durable` with the same ID and store resumes the same thread of the CLI.

If the CLI cannot find the stored thread or session, the run fails with `ErrNoConversation`. The agent then forgets the ID, and the next run starts a new conversation of the CLI. The log keeps its messages, but the model of the CLI no longer reads them.

The CLI keeps the transcript that its model reads. The log is a copy of the run for display and replay.

`State` returns the [state](events.mdx#state) of the agent, as for `agent.Agent`. A CLI agent has no queues, so `Steer` and `FollowUp` on the state do nothing.

## Rules

- Runs on one agent are sequential. If a run is active, a second `Run` fails on its stream.
- A run needs an entry with text or a file. The text and the files of the entries go to the CLI. Claude Code reads images and PDFs, and Codex reads images. Each other file becomes a note in the text, so the model knows that the file was there.
- If the CLI is not logged in, the run fails with `ErrAuth`.
- An ephemeral entry goes to the CLI, and the log does not keep it. The CLI keeps it in its transcript, so a later run still reads it.
- A custom entry goes to the log, and not to the CLI.
- Every run that starts ends with `agent_end`, which holds the error of a failed run.
- A cancel interrupts the turn of the CLI and waits for the turn to end. If the CLI does not stop, the agent stops the process.
- If a run fails or stops during a message, the log keeps the blocks that the CLI completed. The block that streams at that time is not kept.
- Codex can run tools in parallel. The events show them one after the other.
- If the CLI exits, the error of the run holds the end of its stderr.
