## Start One

The CLI must be installed and logged in. The first run starts the CLI, and `Close` stops it.

```go
a := codex.New(
	codex.Dir("."),
	codex.Sandbox(codex.SandboxWorkspaceWrite),
)
defer a.Close()

msgs, err := a.Run(ctx, session.Text("Add a test for Parse.")).Wait()
```

`claude.New` takes the same shared options.

## Options

| Option                             | Package | Sets                                          | Default |
| ---------------------------------- | ------- | --------------------------------------------- | ------- |
| `Store(s)`, `Name(s)`              | both    | The same as for `agent.Agent`                 | |
| `Binary(path)`                     | both    | The path of the CLI                           | `codex` or `claude` on `PATH` |
| `Dir(path)`                        | both    | The working directory of the CLI              | The directory of the caller |
| `Model(name)`, `Thinking(level)`   | both    | The model and the effort of the CLI           | The CLI decides |
| `System(s)`, `Sections(fn)`        | both    | The [sections](sections.mdx) that the CLI adds to its prompt | None |
| `Env(kv...)`, `MCP(servers...)`    | both    | More variables or MCP servers                 | None |
| `Approve(fn)`                      | both    | The function that answers each approval request | Refuse each request |
| `Hooks(hs...)`                     | both    | [Hooks](hooks.mdx#hooks-on-a-cli-agent) that the CLI calls | None |
| `HookCommand(path)`                | codex   | The `gopi` binary that relays a hook          | `gopi` on `PATH` |
| `Sandbox(mode)`                    | codex   | What a command can touch                      | The CLI decides |
| `Policy(policy)`                   | codex   | When the CLI asks                             | `ApprovalNever` |
| `PermissionMode(mode)`, `AllowedTools(names...)` | claude | What the CLI runs without a prompt | The CLI decides |
| `DisallowedTools(names...)`, `AskTools(names...)` | claude | The tools that the CLI cannot use, or always asks for | None |

## Tools and Approvals

The log keeps each call of a CLI tool as a tool call and a tool result. Claude Code uses its own tool names, such as `Bash`. Codex names a command `bash` and a file change `apply_patch`.

`Approve` takes the `agent.ApproveFunc` of the harness. The CLI waits for the answer, so the function must return when its context ends.

```go
a := claude.New(
	claude.AllowedTools("Read", "Grep"),
	claude.Approve(func(ctx context.Context, req agent.ApprovalRequest) (agent.Decision, error) {
		if req.Call.Name == "Bash" && !confirm(req.Call.Input) {
			return agent.Decision{Message: "The user refused the command."}, nil
		}
		return agent.Decision{Allow: true}, nil
	}),
)
```

A `Decision` with no `Allow` denies the call. Only Claude Code sends the `Message` to the model. With `Always`, the CLI also allows the calls that it matches to this call:

- Codex keeps the rule until its process stops. Codex cannot change an action, so it declines a decision with an `Input`.
- Claude Code keeps the rule for its session. `Always` allows only this call if the CLI offers no rule, if the `Input` is new, or if the request has `NoAlways`. The agent sets `NoAlways` when the rule of the CLI allows more than the call.

`codex.New` uses `ApprovalNever`, so Codex acts with no request inside its `Sandbox` mode. The [Codex driver](https://pkg.go.dev/github.com/sonnes/gopi/pkg/agent/codex#Driver) uses `ApprovalUntrusted` when the config has an `Approve` function, and a mode of the config replaces both.

:::caution
Do not use `SandboxDangerFullAccess` or `PermissionBypass` outside a sandbox. With these modes, the CLI can run any command on the machine.
:::

## Sessions

`Durable` keeps the ID of the CLI conversation as a [value](../session/index.mdx), so a second `Durable` resumes it. If the CLI cannot find it, the run fails with `ErrNoConversation`, and the next run starts a new conversation. The model reads the transcript of the CLI, not the log.

`Steer` and `FollowUp` on the [state](events.mdx#state) of a CLI agent do nothing. The Claude Code agent has its own `Steer` and `TakeSteer`. Between runs, [`claude.Idle`](https://pkg.go.dev/github.com/sonnes/gopi/pkg/agent/claude#Idle) gets the events of a subagent in the background, and [`claude.Wake`](https://pkg.go.dev/github.com/sonnes/gopi/pkg/agent/claude#Wake) reports a turn that `Continue` runs.

## Rules

- Runs on one agent are sequential. A second `Run` fails on its stream.
- A run needs an entry with text or a file. A custom entry goes only to the log.
- If the CLI is not logged in, the run fails with `ErrAuth`.
