Defer a tool when the agent has more tools than you want to send on each model call. Without deferred tools, every tool of `agent.Toolset` goes in the [base](sections.mdx#the-base), and each model call sends all of them. A deferred tool is not in the base. The agent can run it, but the model cannot call it until a tool change adds it.

## Defer a Tool

1. Mark a new tool as deferred with `tool.Deferred()`.
2. If a tool is already built, wrap it with `tool.Defer`.
3. Give every tool to `agent.Toolset`.

```go
weather := tool.New("get_weather", getWeather,
	tool.Description("Get the weather forecast."),
	tool.Deferred(),
)
a := agent.New(model,
	agent.Toolset(echo, weather, tool.Defer(stocks)),
)
```

## Search the Deferred Tools

If a tool is deferred, the agent adds the `tool_search` tool after the tools of `Toolset`. Its description names each deferred tool, so the model knows what it can load. The model calls it with a `query` and an optional `max_results`:

| Query                              | Loads                                                         |
| ---------------------------------- | ------------------------------------------------------------- |
| `select:get_weather,stock_price`   | The deferred tools with these names                           |
| `weather forecast`                 | The best keyword matches, up to `max_results`, 5 by default   |
| `+stock price`                     | Only the tools with `stock` in the name, ranked by `price`    |

A keyword in the name of a tool counts twice as much as a keyword in its description or input properties. If two tools have the same score, the tool that comes first in `Toolset` wins. If the model calls a deferred tool before a search loads it, the result tells it to search first.

At the start of the next turn, the agent adds one system message with an `ai.ToolAdded` block for each loaded tool.

## Resume a History

A history from `agent.History` keeps the tools of its base. Before the next model call, the agent compares the tools of the history with its `Toolset`:

| A tool                                       | The system message holds        |
| -------------------------------------------- | ------------------------------- |
| In `Toolset`, not deferred, not in the history | `ai.ToolAdded`                 |
| In the history, with a changed info          | `ai.ToolAdded`, which replaces it |
| In the history, not in `Toolset`             | `ai.ToolRemoved`                |
| In the history and in `Toolset`, with the same info | No block                 |

A tool that the search loaded is in the history, so it stays. If the [sections](sections.mdx) changed too, the same message holds both changes, with the sections first.

## Providers

A provider sends a change in place when its API has a form for it. Otherwise, it sends the current tools as the tool list, and the cache misses on that call.

| Provider     | An added tool                      | A removed tool                  |
| ------------ | ---------------------------------- | ------------------------------- |
| `anthropic`  | `tool_addition` block, in place    | `tool_removal` block, in place  |
| `openai`     | `additional_tools` item, in place  | `allowed_tools` tool choice     |
| `openaichat` | A new tool list                    | `allowed_tools` tool choice     |

The pages for [anthropic](../providers/anthropic.mdx), [openai](../providers/openai.mdx), and [openaichat](../providers/openai-chat.mdx) name the models that take these forms.

## Rules

A loaded tool stays loaded after the run ends, also when a failure or a cancel ends the run before the next model call.

- If the model calls a deferred tool that the search did not load, it gets an error result. A removed tool gets the same result.
- Each tool needs a unique name. If a tool is deferred, a tool of your own named `tool_search` clashes with the search, and `agent.New` panics.
