## Add a Hook

Each point is its own interface, such as `agent.BeforeToolHook`. A hook embeds `agent.BaseHook` and implements the points that it needs. A misspelled method compiles and never runs. Each point gets a copy of `agent.State`.

```go
type Budget struct {
	agent.BaseHook
	Max int // the output tokens after which no tool runs
}

func (b Budget) BeforeTool(ctx context.Context, s agent.State, c ai.ToolCall) (ai.ToolCall, error) {
	if s.Usage().Output > b.Max {
		return c, agent.Deny("the token budget is spent")
	}
	return c, nil
}

a := agent.New(lm, agent.Hooks(Budget{Max: 50_000}))
```

For one point, use its option, such as `agent.BeforeTool`. The hooks run in the order that you add them, and each one gets the value that the one before it returned.

A hook reads the [session](../session/index.mdx#in-a-hook) from `State.Log()`.

## Change a Model Call

A `BeforeCall` hook gets the `agent.Request` of one call: the messages and the options. The history does not change. To change a message, change a copy, because the messages share their arrays with the history. The agent has no cap on the turns of a run. To set one, return an error.

```go
maxTurns := agent.BeforeCall(func(ctx context.Context, s agent.State, r agent.Request) (agent.Request, error) {
	if s.Turn() > 20 {
		return r, errors.New("the run is over 20 turns")
	}
	return r, nil
})
```

An `AfterCall` hook changes the final message of the model before `message_end`. The agent keeps that message and runs its tool calls. If the stream fails, no `AfterCall` hook runs.

## Change or Block a Tool Call

A `BeforeTool` hook can change the input or the name of a call. To block a call, return `agent.Deny` with a reason. The model reads the reason as an error result.

```go
readOnly := agent.BeforeTool(func(ctx context.Context, s agent.State, c ai.ToolCall) (ai.ToolCall, error) {
	if c.Name == "bash" {
		return c, agent.Deny("bash is off in read-only mode")
	}
	return c, nil
})
```

When the calls of a message run at the same time, all their `BeforeTool` hooks run first, one call at a time, in call order.

An `AfterTool` hook changes the result before `tool_execution_end`. It runs in the goroutine of its call, so it must be safe for concurrent use. A tool hook covers every tool, and a [middleware](../tool/index.mdx) wraps one tool.

## Add Entries

An `AfterTurn` hook returns [entries](../session/index.mdx#entries) that the agent adds to the log after `turn_end`. The entries do not start a turn. The next model call reads them, in this run or the next.

A `BeforeStop` hook runs when the turn made no tool calls and the [queues](steer.mdx) are empty. The first hook that returns entries starts a new turn with them, and the hooks after it do not run.

```go
untilGreen := agent.BeforeStop(func(ctx context.Context, s agent.State) ([]session.Entry, error) {
	if testsPass() {
		return nil, nil
	}
	return []session.Entry{session.Text("The tests fail. Fix them.")}, nil
})
```

## Steer From a Hook

In the middle of a turn, a hook adds entries to the [queues](steer.mdx) with `s.Steer` and `s.FollowUp`.

```go
checkErrors := agent.AfterTool(func(ctx context.Context, s agent.State, c ai.ToolCall, r ai.ToolResult) (ai.ToolResult, error) {
	if r.IsError {
		s.Steer(session.Text("That call failed. Read the error before you retry."))
	}
	return r, nil
})
```

## Errors

| Point                     | If a hook returns an error                                |
| ------------------------- | --------------------------------------------------------- |
| `BeforeCall`              | The run fails before the model call.                      |
| `AfterCall`               | The run fails. The history does not keep the message.     |
| `BeforeTool`              | The call does not run. The error text is its error result. |
| `AfterTool`               | The error text is the error result of the call.           |
| `AfterTurn`, `BeforeStop` | The run fails.                                            |

The hooks after the failed hook do not run.

## Hooks on a CLI Agent

The same hooks run on Claude Code and Codex. The CLI calls each point at one of its own hook events:

| Point        | Claude Code                         | Codex         |
| ------------ | ----------------------------------- | ------------- |
| `BeforeCall` | none                                | none          |
| `AfterCall`  | none                                | none          |
| `BeforeTool` | `PreToolUse`                        | `PreToolUse`  |
| `AfterTool`  | `PostToolUse`, `PostToolUseFailure` | `PostToolUse` |
| `AfterTurn`  | `PostToolBatch`                     | none          |
| `BeforeStop` | `Stop`                              | `Stop`        |

A hook at a point that the CLI does not have fails the run. Codex runs each hook as the command `gopi hook`, from the `PATH` or from `codex.HookCommand`. If that command fails, Codex runs the tool. [`claude.Hooks`](https://pkg.go.dev/github.com/sonnes/gopi/pkg/agent/claude#Hooks) and [`codex.Hooks`](https://pkg.go.dev/github.com/sonnes/gopi/pkg/agent/codex#Hooks) give the other rules.
