## Add a Hook

`agent.Hook` has a method for each point. A hook embeds `agent.BaseHook` and overrides the methods that it needs. Each method gets a copy of `agent.State`. `agent.Hooks` adds hook values to the agent, and one value can act at more than one point.

```go
type Budget struct {
	agent.BaseHook
	Max int // the output tokens after which no tool runs
}

func (b Budget) BeforeTool(ctx context.Context, s agent.State, c ai.ToolCall) (ai.ToolCall, error) {
	if s.Usage().Output > b.Max {
		return c, agent.Deny("the token budget is spent")
	}
	return c, nil
}

a := agent.New(lm, agent.Hooks(Budget{Max: 50_000}))
```

For one point, use the option of that point, such as `agent.BeforeTool`. The hooks run in the order that you add them. Each hook gets the value that the hook before it returned.

A hook reads the [session](../session/index.mdx#in-a-hook) from `State.Log()`: the entries, the messages, and the values. It can set values through it, and it cannot append an entry.

A hook that embeds `agent.BaseHook` keeps compiling when gopi adds a hook point, but a misspelled method also compiles and never runs.

## Change One Model Call

A `BeforeCall` hook gets the `agent.Request` of one call: the messages and the options. The agent sends the request that the last hook returns, and the history does not change. To add an option, use `ai.JoinOptions`. To change a message, change a copy of it, because the messages share their arrays with the history.

The agent has no cap on the turns of a run. To set one, return an error from a `BeforeCall` hook.

```go
maxTurns := agent.BeforeCall(func(ctx context.Context, s agent.State, r agent.Request) (agent.Request, error) {
	if s.Turn() > 20 {
		return r, errors.New("the run is over 20 turns")
	}
	return r, nil
})
```

## Change the Message

An `AfterCall` hook gets the final message of the model before `message_end`. `message_end` and the history have the message that the last hook returns, and the agent runs the tool calls of that message. If the stream fails, no `AfterCall` hook runs.

## Change or Block a Tool Call

A `BeforeTool` hook can change the input or the name of a call. It runs after the agent finds the tool, so a call to an unknown tool gets an error result and no hook runs.

To block a call, return `agent.Deny` with a reason. The model reads the reason as an error result.

```go
readOnly := agent.BeforeTool(func(ctx context.Context, s agent.State, c ai.ToolCall) (ai.ToolCall, error) {
	if c.Name == "bash" {
		return c, agent.Deny("bash is off in read-only mode")
	}
	return c, nil
})
```

When the calls of a message run at the same time, the `BeforeTool` hooks of every call run before any call runs, one call at a time, in call order.

## Change a Result

An `AfterTool` hook changes the result before `tool_execution_end`. It runs in the goroutine of its call, so it must be safe for concurrent use.

A tool hook covers every tool of the agent, and a [middleware](../tool/index.mdx) wraps one tool.

## Add Entries

An `AfterTurn` hook returns [entries](../session/index.mdx#entries) to add after `turn_end`. The agent stores them in the log. Each message entry gets `message_start` and `message_end` on the [stream](events.mdx). A custom entry gets no event, and the model does not read it. The entries do not start a turn. The next model call reads them, in this run or in the next run. An ephemeral entry goes to the state and not to the store, and `agent_end` removes it. So only a later model call of this run reads it.

A `BeforeStop` hook runs when the turn made no tool calls and the [steer and follow-up queues](steer.mdx) are empty. The first hook that returns entries starts a new turn with them. The hooks after it do not run.

```go
untilGreen := agent.BeforeStop(func(ctx context.Context, s agent.State) ([]session.Entry, error) {
	if testsPass() {
		return nil, nil
	}
	return []session.Entry{session.Text("The tests fail. Fix them.")}, nil
})
```

## Steer From a Hook

A hook steers the run through its state. `s.Steer` and `s.FollowUp` add entries to the [queues](steer.mdx) of the agent, as `a.Steer` and `a.FollowUp` do. Use them from a hook in the middle of a turn, where a returned entry has no place.

```go
checkErrors := agent.AfterTool(func(ctx context.Context, s agent.State, c ai.ToolCall, r ai.ToolResult) (ai.ToolResult, error) {
	if r.IsError {
		s.Steer(session.Text("That call failed. Read the error before you retry."))
	}
	return r, nil
})
```

A state that a viewer decoded from JSON has no queues, so the two calls do nothing there.

## Errors

| Point                     | If a hook returns an error                                |
| ------------------------- | --------------------------------------------------------- |
| `BeforeCall`              | The run fails before the model call.                      |
| `AfterCall`               | The run fails. The history does not keep the message.     |
| `BeforeTool`              | The call does not run. The error text is its error result. |
| `AfterTool`               | The error text is the error result of the call.           |
| `AfterTurn`, `BeforeStop` | The run fails.                                            |

The hooks after the failed hook do not run.
