An [agent](../agent/index.mdx) is a model with tools. A coding agent also needs the rules of the repository, skills that it loads on demand, subagents for side tasks, and a decision for each command that it wants to run. Without a harness, you build each of these with agent options. With a harness, you give options, and each call of `New` or `Durable` assembles the agent again from the files on disk.

## Assemble an Agent

Give the options that all sessions share to `harness.New`. Then call `Durable` with the ID of a session.

```go
h := harness.New(
	harness.Catalog(cat),
	harness.Model("fake/one"),
	harness.Dir(dir),
	harness.Mode(permission.AcceptEdits),
	harness.Deny("bash(git push *)"),
)

a, err := h.Durable(ctx, "fix-login")
msgs, err := a.Run(ctx, session.Text("Fix the login test.")).Wait()
```

`Durable` returns an `*agent.Agent`, so you read its events and its log as for any agent. A call can add its own options, such as the `Dir` of another repository. A resumed session keeps its model spec. A `Model` on the call changes it.

## Sources

| Source    | Reads                                                                                         |
| --------- | --------------------------------------------------------------------------------------------- |
| `Project` | `CLAUDE.md`, `AGENTS.md`, the skills in `.codex`, `.claude`, and `.agents`, and the subagents in `.claude/agents` and `.agents/agents`, in `Dir` and each parent up to the git root |
| `User`    | The same layouts in the home folder, and `.gopi`                                              |

The harness reads both by default. A skill in a subfolder of `Dir` gets its path as a qualifier, such as `apps/web:deploy`. If two skills have one name, the project skill and then the skill in code get the bare name.

## Skills and Subagents

A skill in code goes in `Skillset`, and a subagent in code goes in `Agents`:

```go
harness.Skillset(skill.Skill{
	Name:        "deploy",
	Description: "Deploy the service.",
	Body:        "Run make deploy.",
}),
harness.Agents(subagent.Agent{
	Name:        "reviewer",
	Description: "Review a diff.",
	Prompt:      "You review code.",
}),
```

The model loads a skill with the `skill` tool, and gives a task to a subagent with the `task` tool. A subagent runs in a child session of the store, and the result gives its `agent_id`, so the model can resume it. `SubagentEvents` gets the events of each child run.

## Permissions

| Mode                | Read tools | Edit tools | bash | Other tools |
| ------------------- | ---------- | ---------- | ---- | ----------- |
| `Default`           | run        | ask        | ask  | ask         |
| `AcceptEdits`       | run        | run        | ask  | ask         |
| `Plan`              | run        | deny       | deny | deny        |
| `Bypass`            | run        | run        | run  | run         |

A `Deny` rule wins over every mode. Then an `Ask` rule, then an `Allow` rule. The rules have the format of Claude Code settings. `Approve` asks a person. Without it, each call that needs an approval is denied.

The built-in tools run in a local sandbox with the workspace fence, so a command cannot write outside `Dir`. The fence runs only on macOS. On another OS, give a sandbox with `Sandbox`.

Each call of `New` or `Durable` reads the files again, so an edit to `AGENTS.md` or a skill reaches the next agent.
